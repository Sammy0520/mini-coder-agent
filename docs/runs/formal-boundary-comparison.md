# Formal same-provider boundary-fix comparison

Date: 2026-08-30 (Asia/Shanghai)

Mini Coder and Codex were run separately against the same `boundary-fix`
fixture. Both used the same project-local aicode007 credential, Responses API,
`gpt-5.6-sol`, `xhigh` reasoning effort, `high` verbosity, task text, timeout,
fresh workspace, and isolated Git baseline. Hidden validation was injected only
after each agent exited.

The runs were separated in time so every provider call could be reconciled with
the aicode007 billing panel. The panel reports cached input separately from
uncached input; both sums exactly matched the aggregate usage recorded locally.

## Result

| Metric | Mini Coder | Codex | Codex / Mini |
|---|---:|---:|---:|
| Hidden validation | passed | passed | same |
| Exact changed paths | passed | passed | same |
| Duration | 33.59s | 171.70s | 5.11x |
| Provider calls | 4 | 11 | 2.75x |
| Tool calls | 4 | 16 | 4.00x |
| Total input tokens | 32,999 | 218,667 | 6.63x |
| Cached input tokens | 28,672 | 194,816 | 6.79x |
| Uncached input tokens | 4,327 | 23,851 | 5.51x |
| Cache reuse | 86.89% | 89.09% | Codex +2.20pp |
| Output tokens | 515 | 2,960 | 5.75x |
| Reasoning tokens | 92 | 664 | 7.22x |
| Actual aicode007 cost | CNY 0.0437 | CNY 0.2597 | 5.94x |

Both agents made the correct one-line implementation change and passed the same
hidden tests. Codex had a slightly higher cache reuse percentage, but its longer
execution path produced substantially more cached and uncached input overall.
It inspected repository state, read the files, performed the change, ran several
boundary and test commands, inspected diffs, removed generated bytecode, and
repeated verification. Mini Coder completed the same scored outcome with four
model calls and four tool calls.

## Interpretation limits

This is evidence for one small, explicit bug-fix task, not an overall coding
agent ranking. It supports the narrower claim that Mini Coder's lightweight,
bounded workflow can reduce cost and latency on well-scoped maintenance tasks
without sacrificing the scored result. The next useful comparison should be a
cross-file feature task; a zero-to-one task should follow only if both agents
remain correct on the more demanding change.

The earlier authentication/cache smoke run is documented separately in
[`cache-stable-benchmark-smoke.md`](cache-stable-benchmark-smoke.md).
